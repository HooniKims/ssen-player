# 1.2.1 검증 · 2026-10-20

## 단일 실행과 파일 전달

- Python 전체 회귀시험 33개 통과 후, 분할 패킷·재전송 시험을 추가해 단일 실행 시험 4개를 별도로 통과했다. 총 34개 시험을 검증했다.
- 실제 별도 프로세스 6개를 동시에 시작했을 때 소유 프로세스 하나만 남고 나머지 5개 파일 요청이 전달됐다.
- 시작 중 지연, 한글·공백 경로, 여러 파일, 파일 없는 실행, 강제 종료 후 재실행, 분할 패킷 수신과 동일 요청의 중복 처리 방지를 확인했다.
- Player 회귀시험에서 기존 로컬/YouTube 재생을 다시 로드하지 않고 파일을 목록 끝에 추가하며, 빈 재생 상태에서는 첫 파일을 재생하는 것을 확인했다.

## 실제 배포 EXE

- 3분짜리 시험 영상 재생 중 파일 연결과 같은 `SsenPlayer.exe "파일 경로"` 명령으로 두 번째 영상을 열었다. 기존 영상 재생이 계속되고 목록은 첫 번째 → 두 번째 순서였다. 새 실행은 종료 코드 0으로 종료했고 플레이어 프로세스는 하나였다.
- 00:58.133에 일시 정지한 뒤 세 번째 영상을 열었다. 목록 끝에 추가되고 첫 영상과 일시 정지 위치가 유지됐다.
- 창을 최소화한 뒤 이미 추가된 파일과 파일 없는 실행을 전달했다. 창이 복원되고 목록은 3개 그대로였으며 일시 정지도 유지됐다.
- 화면 검증은 Computer Use의 실제 스크린샷으로 수행했다. 이 PC의 Qt 접근성 트리는 이전 상태를 반환하는 경우가 있어 최종 판단에는 사용하지 않았다.
- 일반 실행 검증은 별도 LOCALAPPDATA 아래 빈 인증 저장소를 사용했다. 실제 계정으로 로그인하지 않았다.
- 격리된 `--auth-test-output` 검사에서 MOV와 AV1 실제 디코딩, 인증 전 재생 허용, 필기·캡처·내보내기·설정 보호, 가짜 서버의 서명 거부가 통과했다. AV1 첫 실행은 90초 제한을 넘어 재실행했으며 두 번째 실행의 보고서가 모든 검사를 통과했다.
- 번들 버전 1.2.1, 단일 실행 모듈 포함, 소스 시험용 권한 모듈 제외를 검사했다. 재생 DLL 5개의 SHA-256이 고정 vendor 원본과 일치했다.

## 기존 기능과 배포물

- 공통 인증 키트 Node 시험 17개와 브라우저 암호 벡터 61개 통과.
- MOV 재생, 재생 중 필기, 재생/정지 중 캡처, 합성 터치, 전체 화면 검사 통과. `scripts/smoke_test.py` 최종 실행의 종료 코드 0을 확인했다. 중간 재검사에서 전체 화면 안내 숨김 시점 검사가 실패해 재실행했다.
- 약관 일치, EXE 저작권, 비공개 문서 제외, 검사 대상 사용자 출력 53개의 표식 미포함을 확인했다.
- 포터블 ZIP의 전체 CRC 검사와 실행 파일 경로를 확인했다.

## 검증 범위

기존 사용자 설치를 교체하거나 제거하는 시험은 수행하지 않았다. Windows 기본 앱 선택은 변경하지 않고, 등록된 파일 열기 명령과 동일한 인자 전달을 검사했다. 실제 이메일 인증·학교망·다른 앱 계정 공유, 전자칠판 실기기, 다른 PC와 HDR 원본 검증은 이번 수정 범위에 포함하지 않았다.
